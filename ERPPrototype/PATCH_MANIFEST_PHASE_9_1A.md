# Phase 9.1A — Financial Vertical Slice — Candidate Patch

**الحالة:** Candidate — لا تُعتبر مقبولة قبل نجاح الاختبارات على جهاز المشروع.  
**الأساس المطلوب:** النسخة التي نجحت في Phase 9.0C بنتيجة `11/11 Integration` و`33/33 Browser Stress`.  
**نوع الحزمة:** Overlay Patch تراكمي؛ تحتوي الملفات المعدلة والجديدة فقط، وليست نسخة مشروع كاملة.

## ما الذي تضيفه الحزمة؟

تضيف إلى شيت أوامر العمل ثلاثة أعمدة رئيسية:

- `Work Order Value`: مطلوب في أي أمر عمل جديد، وأكبر من صفر.
- `Partial Amount`: اختياري، وأكبر من صفر عند إدخاله، ولا يتجاوز قيمة أمر العمل.
- `Remaining Amount`: محسوب تلقائيًا وغير قابل للتعديل أو التخزين.

المعادلة:

```text
Remaining Amount = Work Order Value - (Partial Amount or 0)
```

المبالغ تُخزن في SQL Server بصيغة `decimal(18,2)`. التقريب إلى منزلتين يستخدم `AwayFromZero`، مثل:

```text
1,250,000.565 → 1,250,000.57
```

داخل المتصفح تُحسب القيم بالهللات الصحيحة لتجنب أخطاء الكسور في JavaScript. عمليات Edit وPaste وUndo وRedo تعيد حساب `Remaining Amount` بدون تخزينه وبدون المرور على كل صفوف الشيت.

## حدود هذه المرحلة

هذه الحزمة لا تضيف بعد:

- شريط الإجماليات السفلي.
- إجماليات الصفوف المحددة.
- Basket Dashboard.
- الأعمدة المخصصة.
- حفظ ترتيب/عرض/إخفاء الأعمدة.
- فلاتر المبالغ الجديدة.

هذه العناصر لها مراحل منفصلة بعد قبول الأساس المالي.

## طريقة التركيب

1. تأكد أن حالة Phase 9.0C محفوظة في Git، ولا تعمل Commit أو Tag للحزمة الجديدة الآن.
2. فك الحزمة داخل مجلد المشروع الذي يحتوي `ERPPrototype.csproj`، ووافق على استبدال الملفات مع الحفاظ على المجلدات.
3. افتح Visual Studio ثم نفذ من **Package Manager Console**:

```powershell
Update-Database
```

4. لتعبئة أوامر العمل القديمة بقيم تجريبية مرة واحدة، افتح قاعدة التطوير المحلية من **SQL Server Object Explorer** ثم شغّل الملف:

```text
Tools/Backfill-DevelopmentWorkOrderFinancialValues.sql
```

السكربت تجريبي فقط، ويملأ الصفوف التي لا تحتوي قيمة، ولا يغير صفًا سبق ملؤه. لا تعتبر القيم الناتجة بيانات مالية حقيقية.

## فحص يدوي مختصر بعد نجاح الاختبارات

1. أضف أمر عمل جديد بدون `Work Order Value` وتأكد أن الحفظ يُمنع.
2. أدخل `1250000.565` وتأكد أنها تظهر `1,250,000.57`.
3. ألصق `250000.255` في `Partial Amount` وتأكد أنها تظهر `250,000.26`.
4. تأكد أن `Remaining Amount` يظهر `1,000,000.31` ولا يمكن تعديله.
5. جرّب Undo ثم Redo ثم Save وRefresh.
6. أدخل جزئيًا أكبر من القيمة وتأكد أن الحفظ يُرفض برسالة واضحة.
