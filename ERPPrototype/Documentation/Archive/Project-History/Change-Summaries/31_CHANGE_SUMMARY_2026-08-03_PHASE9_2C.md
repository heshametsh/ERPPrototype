# 31 — Change Summary — Phase 9.2C CSS Consolidation

**الحالة:** Candidate — يحتاج اختبارات المشروع وقبول الصورة داخل التطبيق  
**التاريخ:** 2026-08-03  
**الخط المرجعي:** Phase 9.2B6-R1 بعد إلغاء تجربة Vertical KPI  
**النطاق:** تنظيف CSS فقط مع الحفاظ على الشكل والسلوك الحاليين

## لماذا نُفذت المرحلة؟

التعديلات البصرية المتتابعة أضافت قواعد جديدة فوق قواعد المراحل السابقة بدل استبدالها. أصبح الشكل النهائي معتمدًا على ترتيب عشرات الـOverrides وعلى عدد كبير من `!important`، وبعض القواعد المتأخرة كانت تستهدف Classes غير موجودة في الصفحة الحالية.

هذا لم يكسر منطق أوامر العمل، لكنه جعل أي تعديل بصري جديد معرضًا لتأثيرات جانبية وصعب التتبع أو الرجوع.

## ماذا تغير؟

تم استبدال ملفي التنسيق بنسخة موحدة تمثل شكل B6-R1 الحالي فقط:

- `Components/Pages/WorkOrders.razor.css`
- `wwwroot/app.css`

تم الاحتفاظ بتنسيق:

- رأس الصفحة والأزرار واختيار السنة.
- الإجماليات الأفقية وألوانها الدلالية.
- مجموعات السلال وتوزيعها المتجاوب.
- مربع البحث المستقل فوق الشيت.
- الجدول الفاتح والصفوف المتبادلة.
- تحديد الخلية بتظليل فاتح وإطار خفيف.
- شريط Selected المحجوز أسفل الجدول.
- نوافذ الفلاتر وعناصرها التي ينشئها JavaScript.

## ما الذي لم يتغير؟

لم يتم تعديل:

- `WorkOrders.razor` أو أي Markup.
- JavaScript أو Tabulator behavior.
- C# أو EF Core أو قاعدة البيانات أو Migrations.
- الحسابات المالية أو السلال أو البحث أو الفلاتر.
- الحفظ وUndo/Redo والإضافة والحذف.
- ارتفاع صفوف الشيت أو ميزانية مساحة العمل المقصودة.

## التحقق المنفذ قبل التسليم

- تحليل CSS ناجح للملفين.
- توازن الأقواس ناجح.
- مقارنة مرئية ثابتة باستخدام DOM مماثل وTabulator CSS الحقيقي عند عروض 1024 و1180 و1366 و1600 و1904 بكسل.
- مواضع العناصر وارتفاعاتها الرئيسية تطابقت في المقارنة الثابتة، مع فروق لونية طفيفة فقط ناتجة عن إزالة التعارضات.

لم تُشغّل اختبارات .NET داخل بيئة إعداد الـPatch لعدم توفر .NET SDK، لذلك اختبارات المشروع المحلية تظل بوابة القبول الإلزامية.
